# SplatTour: 3D 가우시안 스플래팅 기반 공간 이동형 360° 가상 투어

> 연주희 석사 졸업논문 구현 프로젝트 · 시작 2026-09-24

## 1. 한 줄 정의

사람이 공간을 촬영해 올리면 3DGS로 공간 전체를 복원하고, 방문자는 웹·VR에서 시점을 눌러 **로드뷰처럼 이동하며** 그 공간을 360°로 둘러본다.

## 2. 기존 방식과 무엇이 다른가 (논문의 핵심 기여)

| | 기존 360 파노라마 투어 (예: DHARAM, Kuula, 3DVista) | 이 프로젝트 (SplatTour) |
|---|---|---|
| 한 시점의 표현 | 구에 붙인 사진 한 장 | 공간 전체를 3D로 복원한 가우시안 수백만 개 |
| 시점 사이 이동 | 크로스페이드 또는 확대 후 화면 전환(순간이동) | **실제 3D 공간을 통과하는 연속 비행** |
| 시점 개수 | 촬영한 지점만 | 촬영 안 한 곳도 새 시점으로 렌더 가능 |
| 시차(패럴랙스)·VR 깊이감 | 없음 (머리를 움직여도 그림이 같음) | 있음 (6DoF, VR에서 입체감) |
| 제작 | 지점마다 삼각대 촬영 | 걸어가며 영상 촬영 → 자동 처리 |

연구 질문 후보:
- RQ1. 3DGS 기반 연속 이동이 파노라마 크로스페이드보다 **공간 이해·현존감**을 높이는가? (사용자 실험, IPQ 현존감 설문, 방 배치 재현 과제)
- RQ2. 촬영 영상만으로 투어 동선(시점 그래프)을 **자동 생성**할 수 있는가? (카메라 궤적 → 시점 선택 → 가시성 기반 연결)
- RQ3. 일반인 촬영(스마트폰·360 카메라)으로 숙박 공간 투어 품질을 어디까지 낼 수 있는가? (PSNR/SSIM/LPIPS, 촬영 방식별 비교)

## 3. 시스템 구조

```
[촬영물 업로드]  스마트폰 영상 / 사진 / 360 카메라 영상(equirect)
      │  studio (웹 업로드 화면 + 로컬 작업 서버)
      ▼
[1 전처리]  프레임 추출 → 흐림 프레임 제거(라플라시안 분산) → 키프레임 선택
            360 영상이면 equirect → 가상 핀홀 카메라 여러 대(rig)로 분해
[2 SfM]     COLMAP (rig 제약 포함) → 카메라 위치·자세 + 희소 점군
[3 정렬]    바닥면 추정(RANSAC) → 중력 방향 정렬, 눈높이 추정, 스케일
[4 학습]    3DGS 학습  ├ Brush  : 이 노트북(Intel GPU)에서 동작, 빠른 확인용
                        └ gsplat: CUDA GPU(연구실/클라우드), 논문 최종 품질
                          (MCMC 밀도화, 안티에일리어싱, 노출 보정)
[5 후처리]  부유물(floater) 제거, 공간 잘라내기, 웹용 압축(.spz)
[6 투어 그래프] 카메라 궤적에서 시점 노드 자동 선택(최소 간격)
            노드 간 가시성 검사로 이동 가능한 연결선 생성, 이름·썸네일
[7 파노라마] 노드마다 360° equirect 렌더 → 썸네일, 저사양 폴백
      ▼
[viewer]  웹 (three.js + Spark 가우시안 렌더러)
          바닥 화살표·원형 핫스팟 클릭 → 연속 비행 이동
          하단 썸네일 스트립, 미니맵, 드래그로 둘러보기, 전체화면
          WebXR VR(퀘스트 등): 가리키고 순간이동/비행
          모바일: 자이로 둘러보기
```

## 4. 폴더

| 폴더 | 내용 |
|---|---|
| `pipeline/` | 파이썬 처리 파이프라인 (1~7단계), 명령 한 줄 실행 |
| `viewer/` | 투어 뷰어 웹앱 (Vite + three + Spark) |
| `studio/` | 업로드·진행상황·결과 관리 화면 |
| `scenes/<이름>/` | 처리 결과물 (scene.spz, tour.json, panos/, thumbs/) |
| `data/` | 원본 촬영물, 공개 데이터셋 |
| `tools/` | COLMAP, Brush 등 실행파일 |
| `docs/` | 기획, 실험 설계, 논문용 기록 |

## 6. 마일스톤 (기획 → 실행 → 검수 반복)

| 단계 | 결과물 | 검수 기준 |
|---|---|---|
| M0 | 환경 구축, 공개 실내 데이터셋 확보 | 도구 실행 확인 |
| M1 | 뷰어 v1: 스플랫 로드, 시점 노드, 클릭 비행 이동, 썸네일 스트립 | 60fps(노트북), 이동 중 멀미 없는 곡선 |
| M2 | 파이프라인 v1: 영상 → COLMAP → Brush → tour.json 자동 생성 | 공개 데이터로 끝까지 한 번에 |
| M3 | 투어 그래프 자동화: 시점 선택 + 가시성 연결 + 파노라마 렌더 | 벽 뚫는 연결선 0개 |
| M4 | studio 업로드 화면 + 작업 진행률 | 비개발자가 혼자 올려서 투어 생성 |
| M5 | VR(WebXR) + 모바일 자이로 + 미니맵 | 퀘스트 브라우저 동작 |
| M6 | 360 카메라 입력(rig), gsplat 고품질 학습 스크립트 | 같은 공간 품질 비교표 |
| M7 | 평가 도구: 화질 지표, 사용자 실험용 파노라마 비교 모드 | 논문 표·그림 바로 뽑힘 |

## 7. 품질 원칙

- 이동은 순간이동이 아니라 **눈높이를 유지한 곡선 비행**(가속·감속, 이동 중 시선은 진행 방향과 목표 시선 사이를 부드럽게 보간).
- 스플랫이 없는 빈 곳(촬영 안 된 뒤편)으로 가지 않도록 노드는 실제 촬영 궤적 위에서만 고른다.
- 논문에 들어갈 모든 수치는 스크립트로 재현 가능해야 한다 (`pipeline/eval`).
