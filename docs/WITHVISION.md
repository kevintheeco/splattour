# WithVision 분석과 우리 월하정 비교 (2026-09-26)

주희 님이 예전에 WithVision으로 만든 월하정 3DGS(`test02.html`, 70 MB, 모델 `point_cloud.ply`)를 뜯어 보고, 같은 시점에서 우리 모델과 나란히 찍어 비교했다. 비용 0원(노트북에서만).

## 1. 한눈에

- **WithVision의 정체**: 새 기술이 아니다. 표준 3DGS 학습 결과(PLY 한 개, 가우시안 21만 개)를 PlayCanvas 2.15.1 기본 렌더러에 올리고, 타임라인 재생·궤도/비행 카메라 UI를 얹은 **"내보내기용 뷰어 틀"**이다. PLY를 base64로 HTML 안에 통째로 넣어 파일 하나로 열리게 만든 것이 특징.
- **화질**: 같은 시점에서 보면 **전반적인 선명도는 우리 게시본(전체 파일)이 같거나 조금 낫다**(가는 선, 자갈, 회벽 질감). 우리 AI 후보정본은 선이 더 또렷하다.
- **WithVision이 나은 점**: 흰 회벽이 **깨끗하다**. 우리 모델은 흰 벽에 분홍·연두·보라빛 얼룩(색 번짐)이 보이고, 촬영 경로 밖 시점에서 유리창 속이 지저분하다. 사람 눈에는 이 "깔끔함"이 선명함으로 느껴진다.
- **우리가 나은 점**: 대문 통로(어두운 곳)가 WithVision에는 거의 없다(뿌연 안개). 우리는 구조가 보인다. 가우시안 수 24배, 가는 선·질감 재현은 우리가 앞선다.
- **대표님이 느낀 "흐림"의 가장 유력한 원인은 모델이 아니라 우리 PC 기본 로딩 방식(LoD 스트리밍)이다.** 같은 모델을 전체 파일로 보면 WithVision보다 선명한데, 게시 사이트 PC 기본값(LoD)으로 보면 3~5 m 떨어진 살창이 뭉개진다(아래 4장, `docs/checks/withvision/lod-vs-full.jpg`).

## 2. WithVision 뷰어가 하는 일 (HTML 역분석)

| 항목 | 내용 |
|---|---|
| 엔진 | PlayCanvas 2.15.1 (CDN), `gsplat` 컴포넌트 `unified: true`(전역 정렬 방식), WebGL2 |
| 화질 설정 | 캔버스 안티에일리어싱 끔, 픽셀 비율 1(레티나에서도 CSS 해상도), `highQualitySH` 켬(SH 3차까지 사용), LoD 거리표 기본값(5~60)이지만 PLY 한 개라 실제 LoD 없음, 스플랫 예산 0(제한 없음) |
| 좌표 | PLY는 3DGS 원본 관례(COLMAP, y 아래). PlayCanvas가 불러올 때 x·y를 뒤집어(180° Z 회전) 똑바로 보이게 함. 전체를 `sceneCenter`만큼 옮겨 원점 정렬 |
| 카메라 | 세로 시야각 45°, near 0.1 / far 1000. **궤도(orbit)**: 드래그 회전, 우클릭 이동, 휠 확대 + 부드러운 감쇠(8/s). **비행(fly)**: F키 전환, WASD+QE, Shift 3배, 휠로 속도 |
| 타임라인 | 60 fps × 300프레임(5초). 키프레임 사이를 **2차 베지어 곡선**(곡률·각도 지정) + 회전 slerp + 시작/끝 가감속 곡선(`cameraSpeedProfile` +25/−25)으로 보간. 객체마다 보이는 프레임 구간을 둠(여러 PLY를 순서대로 보여주는 "4D" 재생용) |
| 이 파일의 실제 설정 | 키프레임 **0개**(카메라는 초기 위치 고정), 모델은 **0~89프레임에만 보임**. 그래서 열자마자 재생되면 **1.5초 보이고 3.5초 검은 화면이 반복**된다(`docs/checks/withvision/`에는 없음, 캡처로 확인). 스페이스로 멈춰야 조작 가능(재생 중엔 마우스가 안 먹음) |
| 안개 | `scene.fog` exp2, 밀도 0.04, 검정. 실측: 이 설정(0.04)과 안개 끔의 화면 차이는 평균 0.05 단계(0~255)로 **사실상 효과 없음**(밀도를 0.5로 올려도 2 단계). gsplat에는 안개가 거의 안 먹는다 |
| 기타 UI | 2초 뒤 UI 자동 숨김, FPS 표시, R+A+M 동시 누르면 메모리 표시 |
| 성능 | 노트북 헤드리스에서 96~120 fps(가우시안 21만 개라 가벼움) |

## 3. 모델(PLY)로 본 학습 방식

| 항목 | WithVision `point_cloud.ply` | 우리 `wolhajeong/scene.ply` |
|---|---|---|
| 가우시안 수 | **212,673** | 5,000,000 |
| 파일 | PLY 52 MB (우리 SPZ로 바꾸면 **4.6 MB**) | SPZ 131 MB |
| 속성 | x y z, nx ny nz(전부 0), f_dc 3, f_rest 45(SH 3차), opacity, scale 3, rot 4. 값이 양자화되지 않은 float, 쿼터니언 미정규화 → **학습기 원본 출력** | 같은 구성(법선 없음) |
| 불투명도 | 최소 0.04, **0.1 아래가 0.2%**, 중앙값 0.62 | 절반 이상이 0.08 아래(MCMC 특성: 희미한 점을 많이 남김) |
| 크기(최장축, 각 모델 단위) | 중앙값 0.045 (우리 단위로 약 2.6 cm) | 0.009 (약 0.7 cm) |
| SH 에너지(시점에 따라 바뀌는 색) / 기본색 | 중앙값 **3%** | 12% |
| 좌표계 | 첫 카메라 기준, 우리 수평 대비 **3.2° 기울어짐**, 점들이 원점 중심 ±10 단위(COLMAP `Normalize`와 같은 모양) | 바닥 평면 맞춤, 1 단위 ≈ 1 m |

해석:
- 법선 0 채움 + SH 3차 45개 + 미정규화 쿼터니언은 **INRIA 3DGS 원본 / nerfstudio splatfacto 계열 내보내기 형식** 그대로다.
- 불투명도가 0.1에서 칼같이 잘린 것은 splatfacto 기본값(`cull_alpha_thresh 0.1`, 학습 끝까지 계속 제거)과 맞는다. INRIA 원본은 0.005에서 자르므로 이런 분포가 나오지 않는다. → **splatfacto 계열(또는 비슷한 0.1 가지치기)** 로 학습했을 가능성이 가장 높다(단정은 불가).
- 가우시안이 21만 개로 적은 것은 해상도를 크게 줄였거나(예: 1/4) 적은 프레임·짧은 학습으로 보인다. 그래서 **점 하나가 크고 불투명**하다 → 벽이 깨끗하지만 가는 질감은 덜 나온다.
- SH 에너지가 우리의 1/4이라 **시점에 따른 색 요동이 적다** → 우리 흰 벽 얼룩이 거기엔 없는 이유.

### 입력은 무엇이었나
- 우리 월하정과 **같은 좌표계로 맞췄다**: 2D 격자 상관(회전·배율 탐색) → 3D ICP(Sim3). WithVision 점의 **84%가 우리 표면에서 5 cm 안**, 중앙값 1.8 cm. 배율 0.588(WithVision 1 단위 ≈ 우리 1.7 m).
- 덮는 범위가 거의 같다(반경 5 m 안에서 WithVision에만 있는 점 0.8%). **실내는 둘 다 없다**(창문 너머로만). 우리에게만 있는 곳은 **대문 통로**. → 주희 님이 준 **같은 360 영상(앞마당 걷기)** 에서, 어두운 대문 구간은 빠진 채 만든 것으로 보인다. `docs/checks/withvision/coverage-top.png`(회색=둘 다, 초록=우리만, 빨강=WithVision만).

## 4. 같은 시점 비교

비교 이미지는 `docs/checks/`가 git 제외 대상이라 커밋되지 않고 이 노트북에만 있다.

뷰포인트 8곳(WithVision 초기 카메라, 투어 시점 n0·n2·n3·n6·n8, 경로 사이 1곳, 높은 시점 1곳), 1280×720, 세로 시야각 50°.
- `docs/checks/withvision/sheet-*.jpg`: 왼쪽 위 = WithVision 원본 HTML(PlayCanvas, 헤드리스 Chrome GPU), 오른쪽 위 = 같은 WithVision 모델을 우리 뷰어(Spark)로, 왼쪽 아래 = 우리 `wolhajeong`, 오른쪽 아래 = `wolhajeong-ai`.
- `zoom-*.jpg`: 가운데 1/3을 2배 확대(WithVision 원본 | 우리 | 우리 AI).
- `lod-vs-full.jpg`: WithVision | 우리 전체 파일 | **우리 게시 사이트 PC 기본값(LoD 스트리밍)**.

| 렌더 | 선명도 지수(라플라시안 평균, 8시점) | 메모 |
|---|---|---|
| WithVision 원본 HTML | 4.94 | 벽 깨끗, 질감 약간 뭉개짐 |
| 같은 모델 → 우리 Spark | 3.99 (PLY 그대로도 3.93) | SPZ 압축 탓 아님. Spark의 기본 흐림(0.3)+불투명도 보정 탓이 일부(고전식 설정 시 4.23) |
| **우리 전체 파일** | **5.79** | 가는 선·자갈·회벽 질감 우세, 흰 벽 색 얼룩 |
| 우리 AI 후보정 | 6.40 | 선 가장 또렷 |
| **우리 게시 기본값(PC LoD)** | **4.73** | 3~5 m 거리 살창 뭉개짐. 전체 파일 대비 PSNR 27~33 dB(첫 시점 28.5) |

`lodscale=2/4`는 효과 거의 없음, `lodcount=2천만`은 시점에 따라 들쭉날쭉(28.5→31.6이지만 다른 시점은 나빠짐). 풀(pool) 페이지 수 한계로 보인다.

## 5. 우리가 WithVision을 넘으려면 (우선순위)

1. **PC에서는 전체 파일(scene.spz)을 기본으로** 쓰거나, LoD를 쓰려면 풀 크기·예산을 다시 잰다. 대표님이 본 "군데군데 흐림"의 가장 큰 원인. 뷰어 설정 한 줄(`tour.js` 품질 선택)이지만 **연구 조건 화질에 영향**을 주므로 대표님·주희 님 확인 후 적용할 것(이번에는 손대지 않음). 131 MB 한 번에 받기 vs 즉시 첫 화면의 트레이드오프.
2. **흰 벽 색 얼룩 줄이기(학습 설정)**: MCMC 학습 뒤 SH 정리가 필요.
   - 학습 쪽: SH 3차 학습 시작을 늦추거나(예: 1000→3000 스텝마다 차수 증가), `sh_degree` 3 유지하되 f_rest에 작은 L2 정규화. 
   - 후처리(비용 0): 불투명도 0.02 미만 가우시안 제거 + 흰 벽처럼 채도 낮은 곳의 f_rest 크기 줄이기 → 뷰어 렌더로 PSNR 확인 후 채택. 우리 모델 42%가 불투명도 0.05 미만이라 파일도 크게 준다.
3. **떠다니는 얼룩(촬영 경로 밖) 정리**: 경로에서 먼 곳의 크고 희미한 가우시안 제거(점유 격자 밖 + 불투명도 낮음). WithVision은 점이 적고 불투명해서 이 문제가 적다.
4. **렌더러 설정 점검**: 우리 모델은 gsplat antialiased로 학습했으니 Spark 기본(흐림 0.3+보정)이 맞다. 다른 도구 모델(예: WithVision처럼 고전 3DGS)을 올릴 때만 `preBlurAmount 0.3, blurAmount 0`.
5. **뷰어 연출(이번에 추가)**: 시네마틱 자동 카메라. WithVision의 타임라인 재생을 우리 식으로(아래 6장).
6. 해볼 만하지만 급하지 않은 것: UI 자동 숨김(시네마틱 중), 안개(WithVision에서도 실측 효과 없음, 불필요), 궤도(orbit) 보기 모드(연구 조건은 사람 눈높이라 투어 페이지 전용으로만).

## 6. 이번에 넣은 것: 시네마틱 둘러보기 (투어 페이지 전용)

- `viewer/src/cinema.js`, `main.js`에 몇 줄. **`?study=`(실험)와 숙소 앱(`&app=1`)에서는 아예 만들지 않는다** → 실험 조건 영향 없음(확인함: `?study=` 에서 `splattour.cinema === null`).
- 켜기: 주소에 `?cinema=1`, 또는 **C 키**. 끄기: 화면 클릭·드래그·아무 키.
- 경로: 촬영자가 실제로 걸은 길(`capture_path.json`, 784 카메라)을 1.7 m 폭으로 부드럽게 다듬어 0.55 m/s로 이동 → 벽을 뚫지 않는다. 눈높이는 바닥+1.45 m(카메라 봉 높이 0.7~2.1 m는 무시), 계단은 기존 `followFloor`가 처리. 시선은 2 m 앞 + 마당 중심 쪽으로 틀어 벽만 보이지 않게. 현재 위치에서 1.5초에 걸쳐 부드럽게 합류하고 2초에 걸쳐 가속. `capture_path.json`이 없는 장면(drjohnson 등)은 촬영 시점을 촬영 순서로 이은 곡선을 쓴다.
- 확인: 월하정·drjohnson에서 헤드리스로 12초 재생, 이동·시선 변화·클릭 정지 확인. 월하정 한 바퀴는 약 5분 40초(187 m).

## 7. 재현 (로컬)

- 비교용 장면 `scenes/withvision-ref/`(tour.json + scene.spz 4.6 MB, 우리 월하정 좌표로 정렬; 커밋하지 않음, 게시 금지). 변환: `splat_transform = s·R·diag(1,−1,−1)`, s=0.5884, 쿼터니언 [0.2369, −0.0243, 0.9711, 0.0143], 위치 [0.904, 1.420, 5.078].
- WithVision HTML을 헤드리스로 찍을 때: 로딩 끝 → Space(정지) → 슬라이더 0 → `app.on("update")` 에서 카메라를 덮어씀(원래 루프가 먼저 돌고 우리 핸들러가 뒤에 돈다). 캔버스는 헤더 52 px 아래.
- 스크립트는 작업 폴더 scratchpad(`wv/`: stats.py, reg2d.py, icp.py, wvrender.mjs, render_ours.mjs, sheet.py)에 있음. 필요하면 `viewer/scripts`로 옮길 것.
